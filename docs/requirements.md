# Requirement interpretation

The official three-page challenge was read locally. It requires Python, a store-aligned
persona, responses grounded in operational data and policies, appropriate routing and
out-of-scope handling, a public Git repository with real incremental history, an English
README explaining decisions and setup, and 3–5 conversation examples including a nontrivial
data lookup or policy application. It allows CLI or a simple UI and optional conversation
persistence. The submission deadline comes from the candidate's email and is not present
in the PDF. The candidate must submit the repository link personally before that deadline.

The user's additional execution instructions require a Streamlit-style chat, typed read-only
tools, privacy checks, tests without paid calls, local academic review, examples labeled by
execution mode, and publication when authenticated. These additions do not change the
official challenge's requirements.

Private source PDFs and academic slides remain outside Git. The supplied store-policy PDF
is retained as the reproducible fictional knowledge source. Original customer/order CSVs
remain local; generated public fixtures replace direct customer identifiers and tracking data.
